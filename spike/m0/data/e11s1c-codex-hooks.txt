== 1. Method
A recorder script saved the stdin of each hook run to a file and printed nothing (exit 0):
  #!/bin/sh
  d="$HOME/brain-eval/t0134/payloads"
  n="$1-$(date +%s)-$$"
  cat > "$d/$n.json"
  echo "$(date +%s) $1 pane=${HERDR_PANE_ID:-none} socket=${HERDR_SOCKET_PATH:+set} file=$n.json" >> "$d/index.log"
  exit 0
~/.codex/hooks.json got 4 temporary entries next to the 2 SessionStart entries (herdr, Brain):
  UserPromptSubmit: rec.sh prompt
  PostToolUse:      rec.sh tool-all (no matcher), and rec.sh tool-bash with "matcher": "Bash"
  Stop:             rec.sh stop
At start, Codex showed "Hooks need review / 4 hooks are new or changed". In "1. Review hooks"
(/hooks screen), each of the 4 entries was trusted with "t", one at a time. The SessionStart row
showed "2 installed, 2 active, 0 review": the existing entries kept their trust.
After the test, the byte copy of ~/.codex/hooks.json from before the test was put back
(sha256 the same as before). Codex keeps hook trust in its config.toml (E8-S3); this test did not
read that file. The trust of the 4 removed entries can stay there; it trusts no other entry.

- All payloads: session_id, turn_id, transcript_path, cwd, hook_event_name, model, permission_mode.
  session_id is the same in all turns: the Codex thread id ("codex resume <id>").
  cwd is the folder where Codex started, in every payload.
- UserPromptSubmit: "prompt" is the text as typed. The @-mention stays "@notes-zk.txt"; the file
  text is not in the prompt.
- A UserPromptSubmit hook with no output leaves the prompt unchanged: in T1 the reply
  (last_assistant_message) is the prompt, character for character.
- PostToolUse fires for every tool: also list_mcp_resources, list_mcp_resource_templates and
  mcp__node_repl__js (T2: Codex read the file with node, "Read notes-zk.txt without a shell").
  Those have no tool_input.command. The shell tool has tool_name "Bash". The entry with no matcher
  ran for all 8 tool calls; the "Bash" matcher entry ran only for the 4 shell commands.
- Shell PostToolUse: tool_input = {"command": "<the whole command string>"} only. No workdir, no
  exit code, no duration. tool_response is a string with the output.
- The failing "ls nosuchfile-zq" (T3) fired PostToolUse as a normal command. Codex has no
  PostToolUseFailure event (the /hooks list: PreToolUse, PermissionRequest, PostToolUse, PreCompact,
  PostCompact, SessionStart, SessionEnd, UserPromptSubmit, SubagentStart, SubagentStop, Stop).
- The top-level cwd stays the turn cwd: "cd sub" in the command and the workdir of the tool call
  (T3, pwd printed .../work/sub) do not change it.
- The long command (T4) fired one PostToolUse, after the end, with the whole command.
- Stop: last_assistant_message is the final reply text only, with its blank lines (T3), not the
  "Ran ..." lines. stop_hook_active false. One Stop per finished turn.
- T5, stopped with Esc: no Stop and no PostToolUse. The null last_assistant_message of the Codex
  source (e11s1-codex-hooks.txt) was not seen.
- Codex warned at start: "Running without the shared background server: command-line configuration
  overrides (-c, --enable, --disable, or --search) requires embedded mode." (a -c argument).
