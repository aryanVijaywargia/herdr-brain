== 1. Can a -c override set the hooks with no hook-trust step? No.
Live: run 2 put a UserPromptSubmit hook and a Stop hook in -c 'hooks={...}'. Codex listed them for review
  ("5 hooks are new or changed" = 3 user hooks + these 2). With "Continue without trusting" they never ran:
  hooks/index.log has no "ups" or "stop" line across 3 turns (only the notify lines below).
Source: a -c hook lives in the SessionFlags layer, key "<session-flags>/config.toml:<event>:<group>:<handler>"
  (hooks/src/engine/discovery.rs:421, :665). It runs only when enabled and trust_status is Managed or Trusted,
  or with bypass_hook_trust (discovery.rs:713-719). Trusted means hooks.state.<key>.trusted_hash equals the hash
  of the normalized hook (discovery.rs:796-811). hooks.state is read from the User and the SessionFlags layers
  (hooks/src/config_rules.rs:15-45).
So a -c `hooks.state` entry with the right trusted_hash could mark a -c hook trusted, with no dialog and no file
  write. That is a hook-trust step (it gives the trust approval on the command line). It is outside the owner
  rule, so it was not tried. Owner decision.
